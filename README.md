# PR Reviewer Assignment Service

## Описание проекта

Микросервис, который автоматически назначает ревьюеров на Pull Request’ы (PR), а также позволяет выполнять переназначение ревьюверов и получать список PR’ов, назначенных конкретному пользователю, управлять командами и активностью пользователей. 
Стек: Golang, Postgres.

## Основные эндпоинты

Описание эндпоинтов:

•`POST /team/add`: Добавляет новую команду и/или ее участников. Если пользователь с таким `user_id` уже существует, он будет переназначен в только что созданную команду.

•`GET /team/get?team_name={team_name}`: Инфлрмацию о команде - список всех ее членов.

•`PUT /user/set-active`: Устанавливает статус активности пользователя true/false.

•`GET /user/get-reviews?user_id={user_id}`: Получает список всех Pull Request, назначенных данному пользователю на ревью

•`POST /pullRequest/create`: Создает новый Pull Request. Автоматически выбирает ддо 2х активных ревьюеров из той же команды, что и автор PR, исключая самого автора.

•`PUT /pullRequest/merge`: Отмечает Pull Request как "MERGED".

•`PUT /pullRequest/reassign`: Переназначает одного из текущих ревьюеров PR на другого случайного активного пользователя из той же команды, который не является автором или другим текущим ревьюером. (если такой есть)

### Дополнительно
•`GET /stats/overall`: Общая статистика по Pull Request-ам (общее кол-во, открытые, мерженные, среднее число ревьюеров на PR) и статистику по ревью для каждого пользователя (количество назначенных и выполненных ревью).

### Инструкции по запуску

1. `git clone https://github.com/Immflame/PR_Reviewer_Assignment_Service`
2. `cd pr-reviewer-assignment-service`
3. `docker compose up --build`

Сервис по умолчанию будет доступен по адресу http://localhost:8080

### Проблемы с которыми столкнулся

1. Непонятно что означает is_active у user. Может ли is_active = false означать, что пользователь в данный момент занят ревью другого PR или это означает, что он недоступен для работы (в отпуске, на больничном, уволен и тд)? От этого зависит логика назначения ревьюеров, тк если верным является 1 вариант => каждый user может являться ревьюером макимум в одном PR, если верен 2 вариант => такого ограничения нет. 

Принятое решение: 2 вариант
